## 1. 选型原则

1. **强制基座优先**：前端 React + Ant Design、后端 Java 21 + Spring Boot / Spring Cloud Alibaba 为用户硬性要求，所有选型围绕其展开。
2. **职责分离**：OLTP（MySQL）/ Abox 对象明细（Doris）/ 图谱关系（NebulaGraph）/ 缓存（Redis）/ 对象存储（MinIO）/ 事件流（Kafka）各司其职，避免一库包打天下。
3. **可观测、可审计**：所有组件需满足 PRD 第 8 章「审计管理」的日志与指标需求，优先选择 Prometheus/Grafana/ELK 生态成熟产品。
4. **插件化扩展**：数据源、脱敏算法、Skill 市场均按 PRD 第 10 章「扩展性」要求采用 SPI/Adapter 模式，选型组件需支持插件机制。
5. **国产化可选**：加密算法保留 SM4 国密路径；KMS 支持 HashiCorp Vault 与阿里云 KMS 双轨。

## 5. 存储与中间件

### 5.1 数据库矩阵

| 存储 | 版本 | 职责 | 关键表/数据 |
|---|---|---|---|
| **MySQL** | 8.0+ | OLTP 元数据 | 工作空间、用户、角色、类/属性/动作/函数定义、审批单、API Key、标记策略、审计日志 |
| **Doris** | 2.x | Abox 对象明细数据（OLAP） | 每个 Object Type 映射一张宽表（如 `doris.equipment_master`），承担 PRD 4.1「对象数据查询」的列式扫描 |
| **NebulaGraph** | 3.x | 图谱关系存储 | Link Types 的边（Edge），如 `Equipment -[belongs_to]-> ProductionLine`；nGQL 查询 |
| **Redis** | 7 Cluster | 缓存 + 限流 + 分布式锁 | 本体元数据缓存、API Key 配额令牌桶、Pipeline 实例去重锁、在线会话 |
| **MinIO** | 最新 | 对象存储 | 函数代码包、审批附件、CSV/Excel 导出、审计归档 |
| **Kafka** | 3.x | 事件流 | CDC 变更事件、动作副作用、审计日志异步写入、Workflow 事件驱动 |

### 5.2 中间件使用模式（参考 middleware-integration 技能）

| 模式 | 实现 |
|---|---|
| **Constructor Injection** | 所有 Repository/Adapter 构造注入 `JdbcTemplate` / `RedisTemplate` / `KafkaTemplate` / `NebulaSession`，禁用 `@Autowired` 字段注入 |
| **Anti-Corruption Layer** | 每个存储封装 `XxxAdapter implements XxxRepository`，隔离 Doris / Nebula 客户端细节，便于替换或扩展数据源类型 |
| **Circuit Breaker** | 外部依赖（Doris / Nebula / Kafka / MinIO）统一 `@CircuitBreaker` + fallback（降级到缓存或空结果） |
| **Cache-Aside** | 本体元数据（类、属性、枚举）查询走 Redis，写操作先落 MySQL 再 `@CacheEvict` |
| **事件溯源** | 动作写回（PRD 4.6）产生 `ObjectChangedEvent` 发往 Kafka，下游衍生属性重算 + 审计消费 |

### 5.3 Kafka Topic 规范

- 命名：`oo.{service}.{entity}.{event}`，如 `oo.ontology.equipment.updated`
- Key：业务主键（`equipment_id`）保证同分区有序
- 消息结构：统一 `EventEnvelope { eventId, eventType, eventVersion, timestamp, workspaceId, source, data, metadata { correlationId, userId } }`
- DLQ：`oo.{service}.{entity}.dlq`，保留 7 天
- 消费组：`{service}-{purpose}`，如 `oo-audit-consumer`

### 5.4 Redis 使用规范

- Key 命名：`oo:{module}:{entity}:{id}`，如 `oo:ontology:class:Equipment`
- TTL 策略：元数据 2 小时、API Key 配额 1 秒（令牌桶）、会话 30 分钟、分布式锁按业务超时
- 禁止存储 >1MB 对象；序列化统一 JSON（Jackson）
- Cluster 部署 ≥3 master + 3 replica

## 6. 数据集成 / 开发 / 调度（重点选型）

PRD 第 5 章要求四类 Pipeline（集成、开发、质量、治理）+ DAG 编排画布 + 定时/事件触发。候选均为用户指定集合内产品，下文给出定位划分。

### 6.1 数据集成（DataX + SeaTunnel 双引擎）

| 引擎 | 定位 | 适用场景 |
|---|---|---|
| **DataX** | 离线批量同步 | 异构源批量 T+1（MySQL→Doris 全量、CSV 导入、跨库迁移）；成熟稳定、插件丰富 |
| **Apache SeaTunnel** | 实时 + 批量 | CDC 实时同步（MySQL Binlog → Doris / Kafka）、多源合并；引擎基于 Spark/Flink，天然对接下游计算 |

**推荐组合**：
- **CDC / 准实时**：SeaTunnel + Flink CDC（写入 Doris / Kafka）
- **T+1 批量**：DataX（夜间全量同步、字典表同步）
- 在 `oo-data` 服务中通过 SPI 抽象 `IntegrationEngine` 接口，屏蔽两种引擎差异，UI 统一调度。

### 6.2 数据开发（Spark + Flink 双引擎）

| 引擎 | 定位 | 适用场景 |
|---|---|---|
| **Apache Flink** | 流批一体（低延迟） | 实时 CDC 清洗、衍生属性流式计算、值约束准实时校验（PRD 4.5 Pipeline 校验时机） |
| **Apache Spark** | 大规模批处理 | ODS→DWD→DWS 离线分层、值约束规则全量回刷（PRD 4.5）、血缘采集（PRD 5.3 `pl-lineage`） |

**推荐组合**：
- **实时链路**：Flink（CDC 入湖 / 衍生属性 / 实时质量校验）
- **离线链路**：Spark（T+1 分层加工 / 全量回刷 / 血缘）
- 函数（PRD 4.7）在线沙箱使用 Java 进程池或 GraalVM Polyglot；Spark/Flink 任务调用封装好的 Python/SQL 函数包。

### 6.3 调度（Apache DolphinScheduler 单一选型）

#### 6.3.1 选型决策

经过对 DolphinScheduler、XXL-Job、Argo Workflows 三者的场景匹配度评估，最终选定 **Apache DolphinScheduler** 作为唯一调度引擎。

| 维度 | DolphinScheduler ✅ | XXL-Job ❌ | Argo Workflows ❌ |
|---|---|---|---|
| 可视化 DAG 画布 | 内置 Web UI，可嵌入前端 | 仅列表式任务 | 无可视化编辑器，YAML 定义 |
| 上游任务依赖 | Dependent 节点（原生） | 无此能力 | 需 Argo Events 复杂搭建 |
| 时间 + 依赖 AND 触发 | Cron 触发 → Dependent 等上游 → 启动 | 不支持 | Sensor 条件组合，配置复杂 |
| Spark/Flink/DataX/SeaTunnel 节点 | 全部内置 | 仅 Shell/HTTP | 需容器镜像封装 |
| 补数（重跑历史周期） | 原生支持 | 不支持 | 手动 |
| 部署复杂度 | 中（Standalone 或集群） | 低 | 高（强制 K8s） |

**排除理由**：
- **XXL-Job**：本质是 `@Scheduled` 增强版，无 DAG 编排、无任务依赖、无上游完成感知，无法承载「数据集 SLA → 依赖链触发」的核心需求。
- **Argo Workflows**：强依赖 K8s、无可视化画布编辑器、每个数据任务需打容器镜像，场景定位为 CI/CD 流水线而非数据 Pipeline 调度。

#### 6.3.2 数据集 SLA 驱动调度架构

核心需求：**调度配置挂在数据集上**——数据集配置目标就绪时间与上游依赖，平台自动推导并生成 DolphinScheduler DAG。

```
数据集 SLA 配置：dataset.orders 每天 09:00 前就绪
         │
         ▼
平台自动推导：
  ① 该数据集由 pipeline-C 产出
  ② pipeline-C 的上游依赖：pipeline-A → pipeline-B
         │
         ▼
触发条件（AND 逻辑）：
  ├─ 时间到达 09:00 ✔
  └─ pipeline-A 和 pipeline-B 均已完成 ✔
         │
         ▼
立即启动 pipeline-C → 完成后回写数据集就绪状态
```

**架构分层**：

```
┌─────────────────────────────────────────────────────────────┐
│                     平台调度层 (oo-data 服务)                 │
│                                                              │
│  ┌───────────────┐  ┌────────────────┐  ┌────────────────┐  │
│  │ 数据集 SLA     │  │ 依赖推导引擎    │  │ SLA Watchdog   │  │
│  │ 配置管理       │  │ (血缘自动推导)  │  │ (超时告警)     │  │
│  └──────┬────────┘  └───────┬────────┘  └───────┬────────┘  │
│         │                   │                    │           │
│         └─────────┬─────────┘                    │           │
│                   ▼                               │           │
│  ┌──────────────────────────────┐                 │           │
│  │ 调度编排器 (Orchestrator)     │◄────────────────┘           │
│  │ · 生成 DS ProcessDefinition  │                             │
│  │ · 同步 SLA → DS Cron         │                             │
│  │ · 同步上游 → DS Dependent    │                             │
│  └──────────────┬───────────────┘                             │
└─────────────────┼─────────────────────────────────────────────┘
                  │ REST API
                  ▼
        ┌──────────────────────┐
        │  DolphinScheduler     │  ← 纯执行引擎
        │  · Cron 触发          │
        │  · Dependent 等待上游 │
        │  · 任务执行           │
        └──────────┬───────────┘
                   │ 完成回调 (Webhook)
                   ▼
        ┌──────────────────────┐
        │  数据集就绪状态        │  ← 写入 MySQL
        │  (SLA 达成 / 超时)    │
        └──────────────────────┘
```

#### 6.3.3 核心数据模型

```sql
-- 数据集 SLA 配置（挂在数据集上）
CREATE TABLE oo_dataset_sla (
    id               BIGINT PRIMARY KEY AUTO_INCREMENT,
    dataset_id       BIGINT NOT NULL,             -- 关联数据集

    updated_at       DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
```

#### 6.3.4 DolphinScheduler DAG 自动生成

平台为每个数据集 SLA 自动在 DolphinScheduler 中创建一个 ProcessDefinition：

```
┌────────────────────────────────────────────────┐
│ ProcessDefinition: sla_dataset_orders           │
│ Cron: 0 0 9 * * ?                               │
│                                                 │
│  ┌─────────────┐     ┌──────────────────┐      │
│  │ Dependent    │────▶│ Pipeline-C       │      │
│  │ (等待上游)   │     │ (实际执行)        │      │
│  │              │     │ Flink / Spark /  │      │
│  │ · pipeline-A │     │ DataX / SeaTunnel│      │
│  │ · pipeline-B │     └────────┬─────────┘      │
│  └─────────────┘              │                 │
│                               ▼                 │
│                      ┌──────────────────┐       │
│                      │ Webhook 回调      │       │
│                      │ → 数据集就绪状态  │       │
│                      └──────────────────┘       │
└────────────────────────────────────────────────┘
```

**生成规则**：
- **Cron**：取数据集 SLA 的 `cron_expr`
- **第一个节点**：Dependent 类型，配置 `parent_pipelines` 中各 Pipeline 的最近周期成功
- **后续节点**：实际 Pipeline 执行（Flink/Spark/DataX/SeaTunnel 任务节点）
- **末尾节点**：HTTP 回调，通知平台更新数据集就绪状态

#### 6.3.5 平台依赖推导引擎

```java
/**
 * 基于数据集血缘关系自动推导上游 Pipeline 依赖链。
 * 血缘数据由 Pipeline 执行时自动采集（PRD 5.3 pl-lineage）。
 */
public List<Long> resolveParentPipelines(Long datasetId) {
    // 1. 查询该数据集的上游数据集（血缘表）
    List<Long> upstreamDatasets = lineageRepo.findUpstream(datasetId);
    // 2. 查询每个上游数据集对应的产出 Pipeline
    return upstreamDatasets.stream()
        .map(ds -> datasetSlaRepo.findByDatasetId(ds).getPipelineId())
        .distinct()
        .collect(Collectors.toList());
}
```

**推导时机**：
- 数据集 SLA 创建 / 修改时自动触发
- Pipeline DAG 变更时（新增/删除节点）级联更新
- 支持手动覆盖（`parent_pipelines` 字段可编辑）

#### 6.3.6 SLA Watchdog（关键补强）

DolphinScheduler 的 Dependent 节点会**无限等待**上游完成。如果上游 Pipeline 凌晨失败，下游会一直挂起等待。平台层需补一个 SLA Watchdog：

```java
/**
 * 每分钟扫描所有已启用 SLA 的数据集，
 * 检查是否在 deadline 前仍未完成，触发告警。
 */
@Scheduled(fixedRate = 60_000)
public void checkSlaDeadline() {
    LocalTime now = LocalTime.now();
    List<DatasetSla> overdueSlas = slaRepo.findEnabled()
        .stream()
        .filter(sla -> now.isAfter(sla.getSlaDeadline()))
        .filter(sla -> {
            // 查询 DS ProcessInstance 状态
            Integer status = dsApiClient.getProcessInstanceStatus(
                sla.getDsProcessCode(), LocalDate.now());
            // WAITING_DEPENDENT 或 RUNNING 均为未完成
            return status == null
                || status == DS_STATUS_WAITING
                || status == DS_STATUS_RUNNING;
        })
        .toList();

    overdueSlas.forEach(sla -> {
        // 1. 标记数据集 SLA 超时
        slaRepo.markOverdue(sla.getId());
        // 2. 站内通知 + 钉钉/企微告警
        notifyService.sendSlaAlert(sla);
        // 3. 审计留痕
        auditService.log("SLA_TIMEOUT", sla.getDatasetId());
    });
}
```

**告警内容**：数据集名称、SLA deadline、当前状态（等待上游 / 执行中）、阻塞的上游 Pipeline 名称。

### 6.4 数据链路全景

```
  外部数据源 (MySQL/PG/API/Kafka/CSV)
            │
            ├──[实时] SeaTunnel + Flink CDC ──► Kafka ──► Flink (清洗/衍生/校验) ──► Doris
            │
            └──[批量] DataX / SeaTunnel ──► Doris ODS
                                             │
                                             ▼
                                 Spark (分层/回刷/血缘)
                                             │
                                             ▼
                                  Doris DWD/DWS/ADS
                                             │
                                             ▼
                                   NebulaGraph (图边构建)
                                             │
                                             ▼
                              本体服务 (对象点查/关联查询/动作)
```

**调度层**：DolphinScheduler 统一编排上图全部节点。平台级轻量周期任务（审计归档、密钥轮换、API Key 过期扫描）同样通过 DolphinScheduler 管理，避免引入第二套调度引擎增加运维复杂度。

## 9. 跨层一致性校验（Architecture Design 规范）

| 校验项 | 结论 |
|---|---|
| **API ↔ Data** | 分页参数与 Doris 列索引对齐；过滤字段建立 Doris 前缀索引 |
| **System ↔ API** | 网关超时 28s → 服务 25s → Doris 查询 20s，熔断阈值 < 服务超时 |
| **System ↔ Data** | MySQL 按服务拆分独立库（`oo_platform`/`oo_ontology`…），禁止跨服务 join |
| **可观测三件套** | 日志（JSON + MDC）+ 指标（Micrometer）+ 追踪（SkyWalking）全部贯通 |
| **多租户隔离** | 工作空间 ID 作为逻辑租户字段注入所有 SQL/Cache Key/Kafka 消息 |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Spring Cloud Alibaba 与 Spring Boot 3 版本兼容 | 启动失败或特性缺失 | 锁定 `2023.0.x` 对应 Spring Boot 3.2+；上线前回归测试 |
| Doris CDC 实时写入延迟 | 对象数据查询一致性 | Flink CDC 精确一次写入 + Doris Unique Key 模型；提供「数据延迟」指标监控 |
| NebulaGraph 边数据量大 | 查询 P95 上升 | Tag/Index 规划；边属性冷热分离；必要时引入 NebulaGraph 的全文索引 |
| DolphinScheduler Dependent 节点无限等待 | 上游 Pipeline 失败时下游挂起超时 | 平台层 SLA Watchdog 每分钟检查 deadline，超时即告警+标记；DS 侧配置 Dependent 超时参数（默认 12 小时）自动失败 |
| 虚拟线程与 Spring Cloud Alibaba 部分组件不兼容 | 偶发阻塞 | 灰度开启虚拟线程；阻塞 SDK 使用 `ExecutorService.newVirtualThreadPerTaskExecutor` 隔离 |
| Kafka 消息积压 | 衍生属性计算延迟 | 分区数 ≥ 消费实例数 × 2；Lag 告警阈值 5000 |
